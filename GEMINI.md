# Gramin Swasthya App - Gemini Development & Troubleshooting Guide

This guide documents key configuration settings, resolved issues, and development instructions for the **Gramin Swasthya App** Flutter project.

---

## 🛠️ Resolved Build Issues

### 1. `XCBuildData/build.db: database is locked`
* **Symptoms**: The build fails with `error: unable to attach DB: error: accessing build database ... database is locked`.
* **Cause**: Two concurrent build/run processes (e.g., one started by the IDE and one run via the command line) are accessing the same target build database folder simultaneously, or a previous run crashed and left a stale lock.
* **Resolution**:
  1. Terminate any active `xcodebuild`, `flutter run`, or `flutter build` processes.
  2. Clean the build artifacts completely:
     ```bash
     cd gramin_swasthya
     flutter clean
     ```
  3. Perform a fresh rebuild.

---

### 2. CocoaPods Deployment Target Warnings
* **Symptoms**: Warnings such as `The macOS deployment target 'MACOSX_DEPLOYMENT_TARGET' is set to 10.11, but the range of supported deployment target versions is 10.13 to ...` in targets like `PromisesObjC`, `abseil`, etc.
* **Resolution**: We configured a custom `post_install` hook in `macos/Podfile` to automatically align all CocoaPods dependency targets with the project's minimum macOS deployment version (`10.15`):
  ```ruby
  post_install do |installer|
    installer.pods_project.targets.each do |target|
      flutter_additional_macos_build_settings(target)
      target.build_configurations.each do |config|
        config.build_settings['MACOSX_DEPLOYMENT_TARGET'] = '10.15'
      end
    end
  end
  ```

### 3. `xcodebuild: WARNING: Using the first of multiple matching destinations`
* **Symptoms**:
  ```text
  xcodebuild: WARNING: Using the first of multiple matching destinations:
  { platform:macOS, arch:arm64, id:..., name:My Mac }
  { platform:macOS, arch:x86_64, id:..., name:My Mac }
  ```
* **Explanation**: This is a **harmless warning** generated by Xcode on Apple Silicon Macs (M1/M2/M3/M4) because Xcode detects multiple available architectures (Apple Silicon native `arm64` and Intel transition `x86_64` via Rosetta 2) for targeting "My Mac". Xcode automatically selects the first matching one (usually the native architecture) and builds the application successfully. It does not impact the application runtime or build validity.

### 4. Dart Compiler Errors: Missing Getters (`Color.r`, `Color.withValues`, `Matrix4.translateByDouble`)
* **Symptoms**:
  ```text
  Error: The getter 'r' isn't defined for the class 'Color'.
  Error: The method 'withValues' isn't defined for the class 'Color'.
  Error: The method 'translateByDouble' isn't defined for the class 'Matrix4'.
  ```
* **Cause**: The project was using newer versions of package dependencies (`fl_chart: ^0.71.0` and `smooth_page_indicator: ^2.0.1`) that require color and matrix APIs introduced in Flutter 3.24/3.27+. The local environment runs Flutter `3.22.2` (Dart `3.4.3`), which does not contain these APIs.
* **Resolution**: Downgraded these dependencies in `pubspec.yaml` to versions compatible with Flutter `3.22.x`:
  * `fl_chart: ^0.69.0` (resolves to `0.69.2`)
  * `smooth_page_indicator: ^1.2.0` (resolves to `1.2.1`)

---

### 5. CodeSign Failure: `resource fork, Finder information, or similar detritus not allowed`
* **Symptoms**:
  ```text
  /path/to/gramin_swasthya.app: resource fork, Finder information, or similar detritus not allowed
  Command CodeSign failed with a nonzero exit code
  ```
* **Cause**: Source assets, font files, or configuration files in the workspace contain macOS extended file attributes (`com.apple.provenance`, Finder tags, etc.) which get copied into the final app bundle. The Xcode `codesign` tool rejects bundles containing files with these attributes.
* **Resolution**: Run `xattr -cr` to clear extended attributes from all source folders. A full cleanup sequence:
  ```bash
  cd gramin_swasthya
  flutter clean
  chmod -R u+w .
  xattr -cr .
  flutter pub get
  ```

## 🎨 App Icon Configuration & Generation

We have integrated and configured the `flutter_launcher_icons` tool to automatically generate the launcher icons for all targeted platforms (Android, iOS, macOS, Windows, and Web) using the updated logo asset.

### Icon Source File
* Path: `assets/images/logo.png` (generated in high-resolution 1024x1024 from the source `logo.svg`).

### Tool Setup & Configuration
The launcher icons configuration is added at the root level of `gramin_swasthya/pubspec.yaml`:
```yaml
flutter_launcher_icons:
  android: "launcher_icon"
  ios: true
  remove_alpha_ios: true  # Prevents App Store rejection due to alpha channels
  image_path: "assets/images/logo.png"
  min_sdk_android: 21
  macos:
    generate: true
    image_path: "assets/images/logo.png"
  windows:
    generate: true
    image_path: "assets/images/logo.png"
  web:
    generate: true
    image_path: "assets/images/logo.png"
```

### How to Regenerate Launcher Icons
If you update `assets/images/logo.png` or `assets/images/logo.svg` in the future, you can regenerate icons for all platforms by running:
```bash
# Generate PNG from SVG if needed (using QuickLook on macOS as a helper)
qlmanage -t -s 1024 -o . assets/images/logo.svg
cp logo.svg.png assets/images/logo.png && rm logo.svg.png

# Run launcher icons generator
cd gramin_swasthya
flutter pub get
dart run flutter_launcher_icons
```

## 💻 Environment Setup & Build Commands

If you run builds or run the application from the terminal or using build scripts, make sure the Homebrew environment variables are loaded so CocoaPods can be found correctly:

### Rebuild and Run Command
```bash
# Navigate to the Flutter project folder
cd gramin_swasthya

# Ensure brew path is loaded (if CocoaPods is installed via homebrew)
eval "$(/opt/homebrew/bin/brew shellenv)"

# Clean workspace
flutter clean

# Ensure permissions and clear resource detritus
chmod -R u+w .
xattr -cr .

# Get dependencies and build
flutter pub get
flutter build macos --debug
```
